# سجل الديون (MyStore)

تطبيق ويب بسيط لإدارة **ديون العملاء** في محل أو دكان صغير.
واجهة عربية (RTL) مخصّصة للموبايل، مع تسجيل دخول، فواتير دين، تسديدات، كشف حساب قابل للطباعة، وإحصائيات يومية.

**التقنية:** صفحة HTML واحدة + [Supabase](https://supabase.com) (Auth، Postgres، Realtime، Edge Functions).

---

## المميزات

- تسجيل دخول باسم مستخدم وكلمة مرور (بدون إظهار بريد Auth)
- أدوار: **مدير** و**بائع**
- فاتورة دين جديدة أو إيصال صرف نقدي
- إضافة عملاء سريعة مع حد ائتمان اختياري
- قائمة عملاء مع أرصدة الديون
- ملف عميل: كشف حركات، تسديد، إلغاء فاتورة، طباعة كشف حساب
- إحصائيات: إجمالي الديون، أكثر المدينين، آخر الحركات، ملخص اليوم
- مزامنة لحظية بين الأجهزة عبر Supabase Realtime

## إعداد قاعدة البيانات

### 1. إنشاء المشروع
أنشئ مشروعاً جديداً في لوحة Supabase.

### 2. المنطقة الزمنية
من **Settings → Database → Timezone** اختر:

```
Africa/Tripoli
```

هذا ضروري لصحة إحصائيات «اليوم» في `006_stats.sql` (تعتمد على `now()::date`).

### 3. تشغيل الترحيلات
في **SQL Editor** نفّذ الملفات **بالترتيب مرة واحدة** على مشروع فارغ:

1. `supabase/migrations/001_schema.sql` — الجداول الأساسية، RLS، Realtime
2. `supabase/migrations/002_users.sql` — أسماء المستخدمين والأدوار ودالة `login_email`
3. `supabase/migrations/003_debts.sql` — حد الائتمان، فواتير الدين، التسديدات
4. `supabase/migrations/004_receipts.sql` — نوع الحركة (فاتورة / صرف)
5. `supabase/migrations/005_edit.sql` — تعديل العملاء، الحذف الآمن، إلغاء الفواتير
6. `supabase/migrations/006_stats.sql` — عرض الإحصائيات `store_stats`

كل ملف مصمّم ليكون قابلاً لإعادة التشغيل قدر الإمكان.

### 4. التحقق السريع

```sql
select routine_name
from information_schema.routines
where routine_schema = 'public'
  and routine_name in (
    'create_debt_invoice', 'add_payment', 'void_invoice',
    'rename_customer', 'delete_customer', 'login_email'
  );

select * from public.store_stats limit 1;
```

## إعداد الواجهة

في أعلى سكربت `index.html` عدّل القيم:

```js
const SUPABASE_URL = 'https://YOUR_PROJECT.supabase.co';
const SUPABASE_KEY = 'YOUR_ANON_OR_PUBLISHABLE_KEY';
const STORE_NAME   = 'سجل الديون';   // يظهر في العنوان والطباعة
```

- **SUPABASE_URL** و **SUPABASE_KEY**: من لوحة المشروع → Settings → API.
- استخدم مفتاح **anon / publishable** فقط في الواجهة (ليس Service Role).

افتح `index.html` في المتصفح، أو ارفعه على أي استضافة ثابتة (Netlify، Vercel، GitHub Pages، إلخ).

## إدارة المستخدمين (Edge Function)

الدالة `user-admin` تسمح للمدير بإنشاء وتعديل المستخدمين من داخل التطبيق.

### النشر

```bash
# من جذر المشروع بعد ربط Supabase CLI
supabase functions deploy user-admin
```

تأكد أن المتغيرات التالية متوفرة للدالة (تُضبط تلقائياً في معظم الحالات):

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

### أول مستخدم (مدير)

1. أنشئ مستخدماً من **Authentication → Users** في لوحة Supabase، أو عبر الدالة بعد نشرها.
2. تأكد أن سجله في جدول `profiles` له `role = 'admin'`.
3. تسجيل الدخول يتم **باسم المستخدم** (عمود `username` في `profiles`)، وليس بالبريد.

---

## الأدوار والصلاحيات

| العملية              | بائع | مدير |
|----------------------|------|------|
| عرض الإحصائيات والعملاء | ✓    | ✓    |
| إنشاء فاتورة / تسديد | ✓    | ✓    |
| إضافة عميل (بدون حد ائتمان) | ✓ | ✓ |
| تعديل حد الائتمان / حذف عميل | — | ✓ |
| إلغاء فاتورة         | حسب السياسة | ✓ |
| إدارة المستخدمين     | —    | ✓    |

الكتابة الحساسة تتم عبر دوال Postgres (`SECURITY DEFINER`) مع RLS، وليس بإدراج مباشر من الواجهة.

---

## التشغيل اليومي

1. افتح التطبيق وسجّل الدخول.
2. من **فاتورة**: اختر العميل، النوع (دين أو صرف)، المبلغ، والبيان ثم احفظ.
3. من **العملاء**: اطّلع على الأرصدة وافتح ملف أي عميل للتسديد أو الطباعة.
4. من **الإحصائيات**: راقب إجمالي الديون وآخر الحركات.
5. المدير فقط يرى تبويب **المستخدمون**.

## الطباعة

من ملف العميل يمكن طباعة **كشف حساب** بتنسيق مناسب لـ A4 (RTL). استخدم طباعة المتصفح (Ctrl/Cmd + P).

## ملاحظات أمنية

- لا تضع مفتاح **Service Role** في `index.html` أو أي كود يعمل في المتصفح.
- راجع سياسات RLS بعد أي تعديل على الجداول.
- كلمات المرور: 6 أحرف على الأقل عند الإنشاء من الواجهة.
- أسماء المستخدمين: حروف وأرقام وشرطة سفلية (وعربية في بعض الحالات)، بدون مسافات.
